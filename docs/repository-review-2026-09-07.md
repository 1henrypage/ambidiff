## Standards

The standards sources are `/Users/henry/AGENTS.md`, `CLAUDE.md`, and the workspace manifests. The review applies code-smell heuristics as engineering judgments, not automatic violations. Findings enforced by formatting or lint tooling are excluded from this section.

1. **S1: Shared semantics are duplicated in frontends. Hard violation.** `CLAUDE.md` requires derivations to live in the core. Gap content slicing occurs in `crates/cli/src/tui/app.rs:1168`, `crates/cli/src/engine.rs:373`, and `crates/core/src/wasm.rs:306`. Comment projection and tallies are independently assembled in the TUI, engine, and WASM wrapper, and the browser re-derives the tallies a fourth time (`main.ts:172`). Browser filtering temporarily substitutes a filtered file set into canonical WASM state. B10, B15, and B16 show the resulting divergence. Resolution: gap slicing, placements, tallies, filtering, and expansion now have one owner in `projection.rs` / `view_state.rs`; the TUI, stdio engine, wasm wrapper, and browser consume them (waves 1 and 3).
2. **S2: Watch initialisation violates an explicit ordering invariant. Hard violation.** `CLAUDE.md` requires consumers to arm watches before their first held snapshot. `crates/cli/src/tui/app.rs:176` loads the review before watch initialisation at line 218, then reloads only the file list. The comment stating that the race is prevented does not match the actual code. See B12. Resolution: `Application::start_watch` then `Application::load` is the only startup order and every frontend goes through it (waves 2 and 3).
3. **S3: Mutation ownership is fragmented. Duplicated Code / Shotgun Surgery judgment.** CLI and TUI edit/delete comment vectors and timestamps themselves; CLI, TUI, stdio, and web each assemble add/lifecycle operations. Repeated validation, source reads, ID/time creation, and warning handling make a single behaviour change span four callers. B19, B20, and B23 justify one native application module backed by pure review operations. Resolution: `ReviewFile` gained checked add, edit, delete, lifecycle, and bump operations, and `Application::execute` is the single mutation path for every transport (waves 1 and 2).
4. **S4: The browser has effectively untyped interfaces. Primitive Obsession / Divergent Change judgment.** `web/src/main.ts:12` declares `Json = any`; the same file owns transport, view state, semantics, overlays, and DOM rendering. The package has no TypeScript check. Rust transports independently decode `Value` with lossy conversions. Introduce typed interfaces at these actual seams; splitting the file alone would leave the problem intact. Resolution: `protocol.rs` decodes every request into typed payloads on the Rust side, `web/src/protocol.ts` types every wire shape with `unknown`-to-validated decoders, and strict TypeScript is part of the gate (waves 0, 2, and 3).
5. **S5: Command availability is not enforced. Hard contract gap.** The shared table advertises commands without corresponding handlers. A command inventory needs exhaustive dispatch and executable capability checks, not another copy of the command list. See B17. Resolution: `application.rs` carries a capability inventory tested for exhaustiveness against the command table and against the stdio and web dispatch tables, and the browser has a handler-coverage test (waves 2 and 3).
6. **S6: Verification does not enforce the claimed breadth of parity. Test-design judgment.** Native/WASM conformance covers parsing, row projections, and highlight hashes. It does not cover cached view transitions, expansion, comment projection, painter text integrity, or command completeness. The only browser test is one ASCII success journey. These are useful tests, but insufficient to support the broader frontend-parity claim. Resolution: a projection corpus under `fixtures/projections/` runs natively and under wasm32, the wasm exports have wasm-side tests, the wire contracts under `fixtures/contracts/` are asserted by Rust and bun tests, and the browser gained state tests and journeys (waves 1 to 3).

Standards total: six findings. S1 is the most consequential architectural violation; the recommended refactor gives shared semantics a single owner while retaining the existing useful core primitives.

### Persistence and filesystem integrity

- **B01 / P1: Stale-lock recovery can admit concurrent writers. Reproduced by the storage reviewer.** At `crates/core/src/store.rs:255`, any lock older than ten seconds is removed without checking whether its owner is alive. `Lock::drop` at line 303 removes the path without checking ownership. A live holder A can be displaced by B; dropping A then removes B's lock, allowing C in. Two stale reclaimers can also remove a newly acquired lock. This contradicts the locked read-modify-write contract. Fix reclamation and release as one ownership protocol, then exercise long-lived holders, process death, and competing reclaimers. Resolution: a persistent `.ambidiff.json.guard` advisory lock serialises creation, recovery, and release of the ownership sidecar; nothing is broken by age; cross-process tests cover a holder exceeding ten seconds, competing reclaimers, and a superseded holder (wave 1).
- **B02 / P1: Salvage drops an invalid quarantine container. Reproduced.** `crates/core/src/review.rs:508` removes `quarantined` and retains it only if it is an array. A valid JSON object in that field disappears on the next save without warnings or read-only status. Other malformed top-level values are also replaced by fallback values, which requires an explicit preservation policy. The contract promises quarantined material survives. Preserve unreadable material verbatim and make writes read-only when canonical serialisation cannot safely represent it. Resolution: present-but-unrepresentable top-level values are retained verbatim, warned about, and make the file read-only with a reason (wave 1).
- **B03 / P2: Revision overflow changes values silently and can panic. Reproduced.** Parsing revision `4294967296` silently clamps it to `4294967295` at `review.rs:420`; the clamp branch emits no warning. Automatic pass opening, reopen, and the manual bump use unchecked addition at lines 181, 221, and 236. Debug builds panic; wrapping builds can produce revision zero. Use checked increments and explicit errors without changing persisted bytes on failure. Resolution: every increment is checked (`RevisionExhausted`), and an out-of-range revision is retained and read-only rather than clamped (wave 1).
- **B07 / P1: Setup can overwrite pre-existing files after a read error. Git exclude case reproduced; context-file case source-confirmed.** `crates/core/src/git_source.rs:392` treats all failures reading `.git/info/exclude` as empty content and rewrites the file at line 417. An existing file containing a non-UTF-8 pattern loses its previous exclusions. `crates/cli/src/verbs.rs:484` does the same to AGENTS.md, and line 504 repeats the pattern for the installed skill. `verbs.rs:95` also discards the `Result` of `ensure_git_exclude`, so an exclusion-write failure during `init` is invisible. This violates managed-block preservation. Default only on absence, preserve exclude bytes, and propagate other errors before writing. Resolution: the exclude file is read as bytes, defaulted only on absence, refused when a symlink, and gains the guard rule; `init` reports an exclude failure as a warning; `agent-setup` preflights every target and writes atomically (waves 1 and 2).
- **B08 / P1: Source access escapes the review root. Source-confirmed.** Authenticated `getSrc` at `crates/cli/src/web.rs:370` accepts any path. `GitSource::read_new_side` at `git_source.rs:320` reads `root.join(path)` without containment checks. Absolute paths, parent traversal, and symlinks can reach unrelated files. Comment snippet capture exposes the same read primitive and can persist that content into the review: the engine's `expand` checks changed-set membership first, but its `comment.add` does not. This is an authenticated capability-scope defect, not an unauthenticated access bypass. Restrict source reads to the review tree, and render symlink contents with Git semantics instead of following their targets. Resolution: review-root reads go through `rootio` (no absolute paths, no `..`, no escaping symlinks, links read as link text); `getSrc` serves listed paths only; snippet capture rejects unsafe paths (waves 1 and 2).

### Git source correctness

- **B04 / P1: Diff rows and source content can describe different revisions. Reproduced by the storage reviewer.** `git_source.rs:314` reads the worktree for staged new-side content, although the diff uses the index. `old_side_ref` at line 64 resolves the left tip of `A...B`, although Git uses the merge base for that diff. Snippets, old line counts, and expanded context can therefore disagree with the displayed patch. The unit test at line 587 currently codifies the incorrect three-dot assumption. Resolve explicit old/new endpoints once for all source operations. Resolution: the source resolves a `Comparison` of two endpoints once; a staged review reads the index and `A...B` reads the merge base (wave 1).
- **B05 / P1: Git pathspec expansion can display another file's patch. Reproduced by the storage reviewer.** `git_source.rs:421` passes filenames after `--`, which separates arguments but does not make pathspecs literal. A changed file named `[AB].txt` can select `A.txt`; the single-file parser then returns that file's patch under the requested file name. Apply literal path handling consistently to listing lookups, preflight, and patch requests. [Git documents the dedicated literal-pathspec option.](https://git-scm.com/docs/git#Documentation/git.txt---literal-pathspecs) Resolution: every git command runs with `--literal-pathspecs`; a changed `[AB].txt` addresses exactly one file (wave 1).
- **B06 / P1: Initialising a review in a repository subdirectory breaks tracked paths. Reproduced by the storage reviewer.** `verbs.rs:75` accepts the current directory as the review root. Git's diff listing can return `sub/f.txt`, while subsequent reads join that to `repo/sub`, producing `repo/sub/sub/f.txt`. The reproduced entry had no readable new content and an empty diff. `changed_files()` mixes two coordinate systems: tracked entries are repository-relative (from `git diff`) while untracked entries are root-relative (from `git ls-files`), and the empty patch arises because the per-file pathspec is resolved relative to the current directory. Define one review-relative path coordinate system, with explicit translation for Git object reads. Resolution: listings use `--relative` and every read is root-relative; a second defect found at integration (object reads from a subdirectory root prepended the repository prefix and found nothing) was fixed with a regression test (waves 1 and 2).
- **B27 / P2: Signature checks bypass resource guards and use incomplete untracked identity. Source-confirmed.** `signature` at `git_source.rs:339` runs the entire tracked diff at line 346 and buffers it during watcher signature computation, bypassing per-file preflight. Untracked signatures use only path, size, and mtime: a harmless touch on an untracked file refreshes (a touch on a tracked file does not, since its content is hashed), while same-size untracked edits with restored timestamps can be missed. A bounded content-derived signature must cover the selected source endpoints, without allocating the whole patch on every poll. Resolution: the signature is content derived and streamed under the same budgets as every other read; no timestamps take part (wave 1).

### Shared model and rendering

- **B09 / P1: The browser corrupts Unicode source text. Reproduced against the actual painter.** `web/src/main.ts:399` uses UTF-16 `text.length` as the upper bound for Rust's UTF-8 byte ranges, then slices encoded bytes at line 410. `é` rendered as `�`, `café` as `caf�`, and `foo 😀 tail` lost its final characters. Use one byte coordinate system through span composition and test actual DOM text, highlights, and search together. Resolution: `paint.ts` composes segments over UTF-8 bytes with boundaries clamped and snapped to char boundaries (waves 2 and 3).
- **B10 / P1: Browser context expansion immediately resets itself. Source-confirmed independently by two reviewers.** `main.ts:569` expands the WASM cache, then `openFile` at line 581 reloads the raw diff and overwrites the expanded view. Return and paint the resulting cached view; use shared expansion logic for rows, anchors, and search. Resolution: `ViewState::expand` returns the expansion and the updated view; `ad_expand` returns `{expansion, view, comments}` and the browser paints that result without a reload (waves 1 and 3).
- **B16 / P2: Oversized views lose counts and comments. Reproduced wire defect; source-confirmed browser defect.** `crates/core/src/view.rs:38` flattens `TooLarge { adds, dels }` alongside its own counts. Serialising a 12,000-add/20-delete view with `to_string` (the WASM path) emits duplicate keys, while `to_value` (the engine's `json!`) collapses them to `adds:0,dels:0`. The browser never sees the collision because `parse_file_diff` never yields `TooLarge`; its separate oversized branch at `main.ts:318` skips WASM caching and installs `comments:[]`, so a later comment refresh asks for an uncached view and throws. The TUI banner shows `+0 -0` for such a file while its notice line shows the real counts. Use one placeholder-capable view path and serialise each wire field exactly once. Resolution: `FileView` serialises its kind explicitly and each count once through one placeholder-capable path; the browser loads placeholders through the same cached view state (waves 1 and 3).
- **B18 / P2: Split-view commenting loses the selected side. Source-confirmed.** `main.ts:585` and `tui/app.rs:992` prefer the right cell when both cells exist. Mouse selection retains only the row. Clicking removed text in the left half of a paired row can therefore create a new-side comment. Track the active cell and ask a shared core helper for the semantic anchor target. Resolution: `anchor_target(row, ActiveCell)` in the core; the TUI and browser record the active split cell from hit testing (waves 1 and 3).
- **B24 / P2: Row construction can panic on input accepted by the parser. Reproduced.** `crates/core/src/rows.rs:176` and line 189 add hunk coordinates without overflow checks. Accepted headers with old start `4294967295` can panic during gap construction; the minimal input is `@@ -4294967295,0 +1,1 @@`. The property generators only use small coordinates and miss this boundary. Validate extents, use wider intermediate arithmetic, and test the entire parse-to-view pipeline at numeric limits. Resolution: u64 intermediates with checked conversion, a typed `ParseError::Extent`, and a line-extrema corpus case (wave 1).

### Live state, commands, and errors

- **B11 / P1: TUI refresh can silently select a different file. Source-confirmed independently.** `tui/app.rs:37` stores file targets as vector indices. `reload_files` at line 313 replaces the sorted vector; `reload_current_view` at line 426 reuses the old index. Inserting or removing an earlier-sorting file changes what the user is reviewing and may change the target of their next comment. Preserve path identity and then restore row/cell identity. Resolution: TUI targets are paths; a refresh resolves the previous path, then its rename origin, else falls back to the overview with a notice (wave 3).
- **B12 / P2: Watch startup and source changes can leave stale state. Source-confirmed.** TUI review loading precedes watch baselining at `app.rs:176,218`; a write between them is absorbed (the engine and web server arm first and hold no cached review, so only the TUI has this window). Arm before the held load and reconfigure the source/watch together when its configuration changes. Resolution: `Application` arms the watch before its held load and reconfigures the source and the watch signature together on a `source` change, bumping the generation; the TUI and both servers use it (waves 1 to 3).
- **B13 / P2: Unrelated events can starve safety polling. Source-confirmed scheduling scenario.** `watch.rs:230` resets a shared poll timestamp after every partial event-triggered check. - **B14 / P2: Late browser responses overwrite newer navigation. Reproduced against actual browser state functions.** `main.ts:115` keys pending responses by path, and line 316 applies responses without navigation ownership. ## Bounded hardening work

These are source-backed risk findings, not demonstrated compromises. They belong after the confirmed data-integrity and workflow repairs.

- **H1: Token generation must fail closed.** `web.rs:79` ignores `/dev/urandom` read failures, and the fallback fills only 8 of the 16 token bytes from a predictable seed. Use an OS cryptographic random source with an explicit failure result. Resolution: the token comes from the operating system's entropy source through `getrandom`, with an explicit failure and no fallback (wave 2).
- **H2: Bound web and stdio resource ownership.** The web listener spawns a thread per connection, performs a partial handwritten HTTP upgrade, uses a timeout that can be extended by successive input, has unbounded subscriber queues drained only on read timeout, and its accept loop `continue`s on error, which can spin. Dead subscribers are reaped on send failure, which is correct. Stdio reads unbounded lines and ignores output-write failures. Add admission/message limits, complete handshake validation, total authentication/write deadlines, coalesced notifications, and shutdown/error propagation. Token authentication remains required; origin checking is additional protection, not a replacement. Resolution: complete handshake validation, a 32-connection cap, an absolute five-second handshake deadline, 1 MiB inbound and 16 MiB outbound limits, a write deadline, coalesced broadcasts, bounded stdio lines, and explicit broken-output handling (wave 2).
- **H3: Make build and verification inputs explicit.** Scripts hardcode an Apple Silicon toolchain path; browser bundling is not type checking; committed browser assets have no freshness gate. Browser test startup reports only a 15-second URL timeout when its server fails. Add portable toolchain selection, prerequisite/version checks, a local verification entrypoint, isolated generated-asset comparison, and useful child-process diagnostics. The repository explicitly has no CI, and the user did not choose a replacement policy; adding CI is deferred. Resolution: `scripts/check.sh` with portable toolchain resolution and prerequisite checks, a deterministic asset build compared in isolation, build-script fixture freshness, strict TypeScript, and a Playwright helper that reports child stderr and early exits (wave 2).

## Residual known issues after the repair

- `read_side_lines` reads a side's full content under the 8 MiB raw budget and slices the requested range in memory rather than stopping early; it is bounded, not optimal.
- An untracked file over the 2 MiB budget is reported as too large with zero counts, because no numstat preflight exists for untracked files; the notice says so rather than showing a real count.
- `agent-setup` keeps its block wording, so the block version stays at 1.
- In the browser's wrapped layout, rows outside the rendered window keep their last measured height until they scroll back into view; every state change re-measures the visible window, so this only shows after a width change with no accompanying repaint.
- Recovery of a sidecar left by a pre-repair binary relies on process liveness (`kill(pid, 0)`); if the dead holder's pid has been reused by an unrelated process, the sidecar is treated as live and is not reclaimed until that process exits. This fails safe (nothing is deleted) and does not affect sidecars written by this build, which carry a nonce.
